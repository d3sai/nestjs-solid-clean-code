# API Versioning

## Суть підходу

Вбудований у NestJS механізм версіонування API (`/v1/`, `/v2/`) дозволяє впроваджувати зміни, що ламають сумісність (breaking changes), без зупинки роботи вже існуючих клієнтських застосунків, які використовують попередню версію.

## Приклад у NestJS

```ts
// main.ts
app.enableVersioning({
  type: VersioningType.URI,
  defaultVersion: '1',
});
```

```ts
@Controller({ path: 'orders', version: '1' })
export class OrdersV1Controller {
  @Get()
  findAll() {
    // стара форма відповіді, якою вже користуються існуючі клієнти
  }
}

@Controller({ path: 'orders', version: '2' })
export class OrdersV2Controller {
  @Get()
  findAll() {
    // нова, несумісна форма відповіді
  }
}
```

Обидва контролери працюють одночасно: старі клієнти й далі звертаються на `/v1/orders`, нові — на `/v2/orders`, і жоден з них не ламається під час переходу.

## Чому це важливо

Без версіонування будь-яка зміна контракту API (перейменування поля, зміна структури відповіді) змушує оновлювати всіх клієнтів одночасно з релізом бекенду — що на практиці рідко можливо синхронно (мобільні застосунки, сторонні інтеграції). Версіонування дає час на поступову міграцію.
